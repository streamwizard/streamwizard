# @repo/discord-message

The shared half of the Discord message builder: what a designed message looks like as data, and every rule about it. No discord.js, no React, no env, so web-admin and the bot import the same code and the bot sends exactly what the builder shows.

| File | What it holds |
|---|---|
| `buttons.ts` | `BUTTON_ACTIONS`: the fixed list of things an action button can do, plus the `built:<action>:<button id>` custom id. The bot answers each one in `src/lib/built-buttons.ts`; a new action is a row here plus its handler |
| `schema.ts` | `BuiltMessage` (banners, embeds, button rows) as zod schemas and types. `parseBuiltMessage` for stored JSON |
| `variables.ts` | `[server.name]` placeholders: `tokenize`, `replaceVariables`, `resolveMessage`, the core variable list |
| `limits.ts` | Discord's limits and `validateMessage`, plus banner image checks (`validateBannerImage`, `sniffBannerImageType`) |
| `plan.ts` | `planDiscordMessages`: a banner is its own Discord message, embeds that follow each other share one, a button row goes under the embeds before it (or stands alone) |
| `model.ts` | Pure edits: add, remove, move, update, `applyTheme` |
| `fields.ts` | How Discord lays embed fields out in rows (`fieldRows`) and the drag-and-drop edit on top of it (`dropField`) |
| `presets.ts` | "Add element" presets (`MESSAGE_PRESETS`) and the templates a new message starts from (`MESSAGE_TEMPLATES`) |
| `themes.ts` | Theme catalog. Files in `assets/themes`, generated by `scripts/generate-themes.py` |

## Who uses what

- **web-admin** renders `MessageBuilder` from `@repo/ui/message-builder`, autosaves the draft to `discord_built_messages`, and runs `validateMessage` before Publish.
- **discord-bot** `src/lib/built-message.ts` has `publishBuiltMessage`: fills placeholders, runs `validateMessage` again, then sends or updates. Any feature can call it.

## Messages in web-admin

`/discord/messages` lists a server's messages; each has a name, a channel and a design. `discord_built_messages` holds one row per message. Publishing goes through `POST /internal/guilds/:guildId/built-messages/:id/publish`, deleting through `.../:id/delete` (the bot removes it from Discord too). These are standing messages, so only `SERVER_VARIABLES` apply.

## Adding a use about a member (join DMs, level-ups)

1. Presets in `presets.ts`, extra variables next to `CORE_VARIABLES` if the feature has any.
2. web-admin: a page that renders `MessageBuilder` with those presets and variables, stored wherever the feature keeps its settings.
3. Bot: call `publishBuiltMessage` from the event handler with `memberVariableValues(member)`.

## Replacing theme artwork

The shipped images are abstract placeholders. Swap a file in `assets/themes` (same name, 545x127 or 2x) or add a row to `THEMES` plus its file, then add the import in web-admin's `src/lib/discord/theme-assets.ts`.

Tests: `bun test`.
